# MY Cloze — 설치 안내 (v2)

빈칸 채우기(Cloze), 문장 순서 맞추기, 어순 배열 테스트를 만들고, 학생 기록을 모으는 웹앱입니다.
주소: https://tfellow.github.io/web/cloze/

## 저장소: Supabase (2026-11 Firestore 에서 이전)
독서 여권 등 다른 MY 앱과 같은 Supabase 프로젝트(`tfellow-web`)와 같은 학교 구글 로그인을 써요. 한 앱에서 로그인하면 Cloze도 이어서 열려요.
교사 권한은 Supabase `admins` 표(= 독서 여권 교사 화면 → ⚙️ 설정 → 교사 계정 관리)가 정해요. `js/config.js` 의 `TEACHER_EMAILS` 는 화면 표시용이라 함께 맞춰 두세요.

## 폴더 구성
```
cloze/
├─ index.html        첫 화면 (교사: 내 테스트 목록 / 학생: 코드 입력·내 기록)
├─ editor.html       테스트 만들기·편집
├─ play.html         학생 응시
├─ results.html      결과 통계 (교사)
├─ live.html         수업용 실시간 순위 화면 (교사, 프로젝터용)
├─ answers.html      정답보기 (교사, 전자칠판용)
├─ migrate.html      예전 Firestore 기록을 Supabase 로 옮기기 (교사, 한 번만)
├─ supabase_cloze.sql  Supabase 표·보안 규칙 (Cloze cz_ 표 + 단어숲 ds_ 표)
├─ firestore.rules   예전 Firebase 규칙 (옮긴 뒤 Cloze·단어숲 옛 기록은 읽기 전용, 영작문 튜터는 그대로)
├─ css/style.css
└─ js/ config.js · sb.js(Supabase 연결) · common.js · core.js · index.js · editor.js · play.js · results.js · live.js
```
`js/sb.js` 는 예전 Firestore 함수 이름(doc, getDoc, getDocs, addDoc, updateDoc, onSnapshot …)을 그대로 쓸 수 있게 Supabase 위에 만든 연결 파일이에요. 표는 `(id, data jsonb)` 모양이고, 사람을 구분하는 `uid`·`ownerUid` 는 소문자 이메일이에요.

## 옮기는 순서 (한 번만)
1. Supabase 대시보드 → SQL Editor 에 `supabase_cloze.sql` 을 통째로 붙여 넣고 Run (여러 번 실행해도 안전).
2. 새 코드 올리기 (cloze/, danuhsup/, teacher/, index.html).
3. Firebase 콘솔 → Firestore → 규칙에 새 `firestore.rules` 를 붙여 넣고 게시 (옛 앱이 남은 기기가 Firestore 에 새로 쓰지 못하게).
4. `cloze/migrate.html` 을 열어 1) Firebase 에 Cloze 테스트를 만든 교사 계정으로 로그인 2) Supabase 관리자 로그인 3) 읽기 → 옮기기.
   다른 교사 계정으로 만든 테스트가 있다고 나오면 1)에서 그 계정으로 바꿔 한 번 더 실행해요. 이미 옮긴 것은 다시 들어가지 않아요.
5. Cloze·단어숲·Teacher Hub 를 열어 기록이 보이는지 확인.

## 5. 사용 순서
1. 교사: 첫 화면 → `+ 빈칸 채우기 만들기` 또는 `+ 문장 순서 만들기`
2. 본문 붙여 넣기 → 자동 빈칸 또는 단어 클릭 → 설정 → 저장 → **6자리 코드** 생성
3. 학생: 첫 화면에서 코드 입력(또는 링크·QR) → 처음 한 번 학번·실명·닉네임 입력 → 응시
4. 교사: `결과`에서 통계·CSV, `실시간 순위`를 프로젝터로 띄우기
5. 어순 배열: `+ 어순 배열 만들기`(어순 배열만) 또는 빈칸 채우기 화면의 **4. 어순 배열 문제**(빈칸 문제 뒤에 이어 붙이기)에 한 줄에 한 문장씩 적습니다. 한 문장이 한 문제입니다.
   단어 사이 ＋로 묶기(New York), 묶인 덩어리를 눌러 나누기, **다른 정답 추가**로 여러 어순을 정답으로 등록합니다. 끝의 . ? ! 는 답 칸 끝에 고정됩니다.
   `결과` 맨 아래 **등록되지 않은 답**에서 학생 답을 **정답으로 인정**하면 다른 정답으로 저장되고 이미 낸 학생 점수도 다시 매겨집니다. 
6. 과제: 테스트 카드의 `과제 내기` → 대상(전체 / 학년 / 학년·반)·마감(선택)·메모 → 학생이 로그인하면 첫 화면 맨 위 **📌 과제**에 보입니다.
   교사 첫 화면 위쪽 **낸 과제** 표에서 제출 인원 확인·과제 취소. 학년·반은 학생 학번으로 판단하고, 그 테스트를 한 번이라도 제출하면 "완료"로 표시됩니다. 마감 3일이 지나면 학생 화면에서 사라집니다.

## 이름 표시 원칙
| 화면 | 보이는 이름 |
|---|---|
| 학생 순위표 (응시 후) | 닉네임만 |
| 실시간 순위 화면 | 기본 닉네임 (교사가 실명으로 바꿀 수 있음) |
| 결과 통계·CSV (교사) | 실명 / 닉네임 / 둘 다 선택 |

실명·이메일은 `cz_submissions`(본인·교사만 읽기)에만 저장되고, 학생이 읽을 수 있는 `cz_board`에는 닉네임과 점수만 저장됩니다.

## 알아 둘 한계
- 채점은 학생 브라우저에서 합니다. 컴퓨터를 잘 아는 학생이 개발자 도구로 정답을 보거나 점수를 조작할 수 있습니다. 막으려면 서버 채점(Supabase 함수로 가능, 무료)이 필요합니다. 수행평가처럼 중요한 평가라면 알려 주세요.
- 화면 이탈 횟수는 "다른 탭·앱으로 이동"만 셉니다. 같은 화면 안의 다른 창은 잡지 못합니다.
- 본문 듣기는 브라우저 내장 음성을 쓰므로 기기마다 목소리가 다릅니다.
