# MY English Arcade · 문영 영어 놀이터

서울문영여자중학교 학생을 위한 12종 영어 학습 게임입니다. 2026-11-21 소유자 승인으로 `tfellow/web`의 독립 폴더 `my-english-arcade/`에 게시하는 버전입니다. **기기 저장 모드이며 Google 로그인·원격 DB는 아직 연결하지 않았습니다.** 연동 담당자는 [AUTH-HANDOFF.md](AUTH-HANDOFF.md)를 먼저 확인해 주세요.

## 바로 실행

`index.html`을 Chrome 또는 Edge로 열면 로그인 없이 모든 게임을 실행할 수 있습니다. 또는 Python이 설치된 PC에서 `START-LOCAL.cmd`를 실행하고 `http://localhost:8765/`로 접속합니다. 서버 종료는 실행 창에서 Ctrl+C입니다. Google 로그인은 `file://` 주소에서 작동하지 않으므로 연동 후에는 HTTP(S) 주소를 사용합니다.

1. 플레이어 학번과 별명을 설정합니다.
2. 학년·단원·문제 수를 선택합니다.
3. 게임을 플레이하고 결과를 확인합니다.
4. 나의 기록에서 오답 TOP과 기록을 확인하거나 결과를 내려받습니다.
5. 교사실에서 문항 JSON/CSV를 교체하고 제출받은 결과 JSON을 가져올 수 있습니다.

현재 로컬 교사실은 보안 로그인 기능이 없는 시연 도구입니다. 이 기기의 기록만 보이며, 공유 기기에는 다른 플레이어 기록도 남습니다. 학교 계정 제한은 Supabase 연결 후 서버 정책으로 적용됩니다.

## 게임 구성

스펠링·문장 조립·짝짓기를 첫 화면 앞쪽에 배치했습니다. 모든 게임은 한국어 뜻, 영영풀이, 예문을 재사용하며 별도의 유료 API가 필요 없습니다.

| 게임 | 학습 방식 | 자료 사용 조건 |
|---|---|---|
| 스펠링 챌린지 | 뜻을 보고 단어·숙어 입력 | 단어, 뜻 |
| 문장 공작소 | 클릭 또는 키보드로 단어 칩 조립 | 예문 26단어 이하 |
| 단어 짝꿍 | 단어와 뜻 연결, 최대 6쌍 | 단어, 뜻 |
| 뜻을 찾아라 | 영단어 → 뜻 선택 | 단어, 뜻 |
| 영단어 탐정 | 뜻 → 영단어 선택 | 단어, 뜻 |
| 영영풀이 퀘스트 | 영어 정의 → 영단어 선택 | 영영풀이 |
| 빈칸의 비밀 | 예문 속 빈칸 타이핑 | 표제어가 예문에 독립된 형태로 등장 |
| 메모리 플립 | 뒤집힌 카드의 단어·뜻 기억 | 단어, 뜻 |
| 리스닝 랩 | 기기 영어 음성 듣고 입력 | 브라우저 SpeechSynthesis 지원 |
| 알파벳 믹서 | 철자 칩 조립 | 영문자 3~14자로 된 단일 단어 |
| 트루 오어 폴스 | 단어·뜻 관계 참거짓 판정 | 단어, 뜻 |
| 암호 문장 연구소 | 일대일 알파벳 이동 치환을 문장으로 복원 | 예문 26단어 이하 |

카드 게임은 최대 6쌍, 나머지는 5·10·15·20문항 중 선택합니다. 자료가 적으면 해당 문항 수만 출제합니다. 듣기 음색과 재생 가능 여부는 기기의 영어 TTS 설치 상태에 따릅니다. 문장 조립은 드래그가 필요 없는 클릭/터치 방식이며 키보드 Tab·Enter로도 사용할 수 있습니다.

예문 속 단어가 복수형이나 활용형으로만 나타나면 빈칸 문제에서 제외합니다. 예컨대 표제어 `comment`와 예문의 `comments`를 무리하게 동일 정답으로 취급하지 않습니다. 문장 채점은 지정 예문을 정답으로 사용하며, 문법적으로 가능한 모든 다른 어순을 자동 인정하지는 않습니다.

커넥션즈는 의미 범주를 교사가 지정해야 신뢰할 수 있는 정답이 됩니다. 워드스케이프·스펠링 비는 허용 단어 사전과 수준 필터가 추가로 필요합니다. 현재 자료만으로 모호한 자동 분류나 무제한 사전 판정을 만들지 않았습니다.

## 실제 데이터와 JSON 구조

상위 폴더의 G1/G2 엑셀을 읽기 전용으로 변환했습니다. 총 674개, 1학년 318개·2학년 356개, 각 8단원입니다. 단어·뜻·영영풀이·예문·해석은 원문을 사용하고 연속 공백만 정리했습니다. 원본 파일은 변경하지 않았습니다. 출처 행 번호는 `data/bank.json`에 포함됩니다.

```json
{
  "version": 1,
  "title": "1학년 1단원",
  "items": [{
    "id": "g1-u1-active",
    "grade": 1,
    "unit": "1",
    "word": "active",
    "meaning": "a. 활동적인",
    "definition": "a. doing things that require physical movement and energy",
    "sentence": "She is very active and friendly.",
    "translation": "그녀는 매우 활동적이며 친절하다.",
    "acceptedAnswers": []
  }]
}
```

문항 JSON 스키마는 `data/schema.json`, 제출 결과 스키마는 `data/result-schema.json`, CSV 예시는 `data/template.csv`입니다. 필수 열은 `id,grade,unit,word,meaning`입니다. CSV의 `acceptedAnswers`는 선택 열이며 `color|colour`처럼 `|`로 구분할 수 있습니다. 문항 ID는 자료 전체에서 유일해야 하고 가급적 유지합니다. HTML은 실행하지 않고 텍스트로 표시합니다. CSV 내보내기는 수식으로 해석될 수 있는 셀에 보호 접두사를 붙입니다.

교사실의 자료 가져오기는 **현재 브라우저에만** 적용됩니다. 전체 학생에게 같은 자료를 제공하려면 교사실에서 **배포용 bank.js**를 내려받아 배포 폴더의 `data/bank.js`를 교체합니다. JSON 원본도 함께 보관하세요. 원본 엑셀을 다시 변환하려면 Python과 openpyxl이 있는 환경에서 `python tools/convert_data.py`를 실행합니다. 변환기는 앱 상위 폴더의 xlsx를 읽습니다.

## 화면 설계

- 게임 라운지: 학교 브랜드 → 누적 XP·첫 정답률·완료 게임 수 → 학년·단원·문제 수 → 분류 탭 → 12종 게임 카드.
- 플레이: 라운지 복귀, 현재 단원, 진행률, 경과 시간, 문제, 입력/카드, 힌트, 즉시 피드백, 다음 문제.
- 결과: XP, 첫 정답률, 총 시간, 복습 포함 응답 수, 저장/전송 상태, 오답 복습, CSV·결과 코드·JSON 제출.
- 나의 기록: 현재 프로필의 요약, 게임별 오답 TOP, 세션 이력, 미전송 재시도.
- 교사실: 학생 검색, 첫 정답률, 문항별 오답률, 결과 CSV, 자료 교체, 외부 Google 계정 허용 설정.

PC에서는 3열, 태블릿·휴대폰에서는 2열 게임 카드입니다. 게임 입력과 조작 버튼은 터치와 키보드를 지원합니다. 브라우저 기본 확대를 막지 않고, 색상 외에도 정답/오답 텍스트를 제공합니다.

## 채점 및 통계 정의

입력 답은 유니코드 NFKC, 대소문자, 앞뒤/연속 공백, 스마트 따옴표를 정규화하여 비교합니다. 철자·어순·문장부호 자체는 정답과 일치해야 합니다. 첫 정답 100 XP, 힌트를 사용한 첫 정답 70 XP, 첫 오답 0 XP입니다. 객관식·타이핑·조립 문제의 첫 오답은 뒤에 한 번 더 출제됩니다. 재오답이 무한 반복되지는 않습니다.

세션의 첫 정답률은 `처음 맞힌 고유 문항 수 / 고유 문항 수`입니다. 같은 게임 내 복습 정답으로 이 비율이나 점수가 올라가지 않습니다. 별도 시작한 복습 게임은 새 세션이며 `(복습)`으로 표시됩니다. 매칭의 첫 오답과 메모리의 실패한 두 카드도 기록되어, 마지막에 모두 맞혀도 최초 실수는 통계에 남습니다. 메모리 게임의 정답률에는 위치 기억 능력이 섞이므로 다른 게임과 함께 해석해야 합니다.

문항별 오답률은 자료 버전·게임·문항 ID별로 첫 응답만 집계합니다. 종합 정답률은 세션 정답률의 단순 평균이 아닌 문항 수 가중 비율입니다. 소요 시간은 쉬는 시간과 화면을 보지 않는 시간도 포함한 경과 시간입니다. 각 응답에는 정오답, 입력, 기대 답, 힌트 여부, 최초/재풀이 구분, 응답 소요 시간이 남습니다.

로컬 프로필은 학번으로 분리하고 Google 연결 후에는 인증 사용자 ID로 분리합니다. 로그인 전 결과는 계정에 자동 귀속·전송하지 않습니다. 공유 기기에서 프로필 변경이나 로그아웃을 해도 기존 로컬 기록 자체는 삭제되지 않습니다. 로컬 데이터는 브라우저 데이터 삭제 시 사라지므로 CSV/결과 파일로 보관할 수 있습니다.

## Supabase 연결 준비 — 아직 실행하지 않은 절차

**사용자와 폴더·DB 구성을 최종 합의한 후 진행합니다.** 후보 폴더는 `my-english-arcade`, 테이블/함수 접두사는 `myea_`입니다. 현재 설정값은 비어 있고 SQL은 파일로만 제공됩니다. 다른 AI가 만든 앱의 폴더·테이블·인증 설정과 겹치지 않는지 먼저 확인해야 합니다.

1. 사용할 Supabase 프로젝트를 확정합니다. 가능하면 독립 프로젝트를 사용합니다. 기존 프로젝트의 Google Provider나 Site URL을 임의로 덮어쓰지 않습니다.
2. `backend/supabase.sql`을 검토하고 한 번 실행합니다. 같은 이름이 있으면 실패하고 트랜잭션을 되돌리도록 작성되어 있습니다. 기존 테이블을 재사용하거나 삭제하지 않습니다.
3. Google OAuth Web client의 origin에 승인된 홈페이지 origin을 등록하고, redirect URI에는 해당 Supabase 프로젝트의 Google callback URL을 등록합니다. Google Client ID/Secret은 Supabase Provider 설정에 넣습니다.
4. Supabase redirect allowlist에 승인된 앱 URL과 필요한 로컬 개발 URL을 추가합니다. 기존 앱 설정은 유지합니다. 두 관리자 계정 중 개인 Gmail도 사용할 수 있도록 Google OAuth 대상 사용자 설정을 함께 확인합니다. 학교 Workspace의 앱 허용 정책이 별도로 적용될 수 있습니다.
5. `config.js`의 `supabaseUrl`, `supabaseAnonKey`에 프로젝트 URL과 공개 publishable/anon key를 넣습니다. **service_role 키·Google client secret을 소스나 GitHub에 넣지 않습니다.**
6. 별도 테스트 계정으로 아래 권한 시나리오를 검증한 뒤 게시합니다.

| 사용자 | 본인 결과 | 타 학생 결과 | 외부 계정 설정 |
|---|---|---|---|
| 비로그인 | 로컬 저장 | 접근 불가 | 불가 |
| 학교 Google 학생 | 서버 기록 추가·조회 | 접근 불가 | 불가 |
| 외부 Google 학생, 옵션 OFF | 서버 접근 불가 | 접근 불가 | 불가 |
| 외부 Google 학생, 옵션 ON | 본인 기록 추가·조회 | 접근 불가 | 불가 |
| tfellow@gmail.com | 전체 조회 | 가능 | 가능 |
| tfellow@smy.ms.kr | 전체 조회 | 가능 | 가능 |

RLS와 서버 함수가 Google identity, 확인된 이메일, 학교 도메인, 관리자 이메일을 검사합니다. 외부 계정은 Google 인증 자체를 시도할 수 있지만, 옵션 OFF이면 앱이 로그아웃 처리하고 DB 접근을 거부합니다. 이 정책은 Supabase Auth에 외부 사용자가 생성되는 것 자체를 막는 before-user-created hook은 아닙니다. 옵션을 끈 뒤에도 기존 외부 사용자의 새 DB 요청은 서버가 거부합니다.

학생은 본인 세션 INSERT/SELECT만, 관리자는 전체 SELECT와 설정 UPDATE만 허용됩니다. 학생의 UPDATE/DELETE는 제공하지 않습니다. 네트워크 실패 시 기기 기록에 전송 실패 상태를 남기고 같은 ID로 재시도해 중복을 방지합니다. teacher 화면은 서버 결과를 페이지 단위로 불러옵니다. 기기 학습 데이터 키는 `myEnglishArcade.v1`, Supabase 인증 저장 키는 `myea.auth.v1`로 분리했습니다.

이 버전은 자기주도 복습용입니다. 정답과 채점 코드가 브라우저에 있고, 서버는 제출자 권한과 기본 데이터 형식을 검증합니다. 점수 자체의 위변조 방지가 필요한 고부담 평가에는 서버 채점·공식 문항 테이블·수업별 출제 토큰을 추가해야 합니다. 학번·별명은 학생이 입력하는 값이며, 인증 식별자는 Google 사용자 UUID입니다.

연동 구현은 [Supabase Google 로그인 공식 문서](https://supabase.com/docs/guides/auth/social-login/auth-google)와 [Row Level Security 문서](https://supabase.com/docs/guides/database/postgres/row-level-security)를 기준으로 준비했습니다. 실제 프로젝트 및 Google 계정 연동은 아직 검증하지 않았습니다.

## 파일 구성과 점검

`index.html`, `styles.css`, `core.js`, `app.js`, `config.js`, `data/`만 있으면 정적 호스팅이 가능합니다. `backend/`는 승인 후 적용할 SQL, `tools/`는 원본 변환기, `tests/`는 채점·데이터 검증 테스트입니다.

```text
node --test tests/core.test.cjs
node --check app.js
```

기능 검증 결과 및 확인하지 못한 항목은 `QA.md`에 기록합니다. GitHub push·원격 게시·DB 적용 명령은 자동 실행하지 않습니다.
